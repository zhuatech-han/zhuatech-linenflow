## 私有备份

创建权限0700的私有备份目录。以下密码只在容器环境取值，不出现在命令文本或输出：

```bash
mkdir -m 700 -p private-backups
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines --triggers --no-tablespaces "$MYSQL_DATABASE"' > private-backups/linenflow.sql
chmod 600 private-backups/linenflow.sql
```

SQL和`.env`包含敏感资料，禁止提交或公开分发；本项目`.gitignore`排除private-backups。妥善存放、加密并按数据制度轮换备份。备份期间避免并发结构迁移，必要时安排维护窗口。

## 独立恢复演练

1. 在独立目录或独立Compose项目生成测试配置，使用不同端口和全新卷；保存原库，不覆盖生产。
2. 先启动新MySQL并等待健康，导入备份后启动后端和前端，Flyway校验历史并迁移。
3. 核对健康、管理员及岗位登录、批次、账单、款项、权限、迁移历史及计价快照。备份保留原账号密码，修改ADMIN_PASSWORD不会重置已有库。
4. 重启三个服务再核对记录一致。仅清理这次演练的独立项目和新测试卷。

```bash
# 在已确认的独立恢复项目内执行，禁止指向正式数据库
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$MYSQL_DATABASE"' < private-backups/linenflow.sql
```

## 升级及正式入口

升级前保存旧版本、备份和配置，在恢复副本中先运行新版本，确认迁移、业务、权限与健康。已执行SQL不可改正文，新增更高版本迁移；回退应用前核实新数据库结构兼容，不能只换镜像假定回退成功。

正式环境配置可信HTTPS代理、COOKIE_SECURE=true、独立强密码和访问控制。数据库若跨网络连接，使用受信证书并校验TLS。运行日志不保存密码或完整业务载荷。`docker compose down`保留数据库，`down -v`删除卷，禁止对正式实例直接使用；清理资源前核对Compose项目名。
